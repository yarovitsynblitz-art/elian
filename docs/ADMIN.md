# Администрирование Элиана

Владелец сервера — единственный, кто подтверждает входы и регистрации. Всё делается в консоли на телефоне.

## 1. Консоль владельца

```bash
tmux attach -t elian          # окно "server"
# выйти из консоли, не убивая сервер: Ctrl-b, затем d
```

Команды:

| Команда | Действие |
|---|---|
| `list` | показать очередь запросов (ID, тип, логин, код, время, устройство, маскированный IP) |
| `show <id\|код>` | подробности одного запроса |
| `y` / `y <id\|код>` | подтвердить (без аргумента — единственный запрос в очереди) |
| `n` / `n <id\|код>` | отклонить |
| `stats` | счётчики очереди и время |
| `help` | справка |

Что **никогда** не показывается: пароль, хэш пароля, токены, cookie, тела запросов. Фильтр редактирования
включает `password`, `newPassword`, `currentPassword`, `token`, `authorization`, `cookie`, `approvalSecret`, `sessionSecret`.

## 2. Как выглядит подтверждение

1. Пользователь вводит логин и пароль. Сервер проверяет Argon2id-хэш (или фиктивный хэш, если пользователя нет —
   ответ и время одинаковые), создаёт заявку на 5 минут и **не** создаёт сессию.
2. В консоли/уведомлении Termux появляется строка: `LOGIN @username КОД`.
3. Вы вводите `y` — создаётся сессия; клиент забирает её по своему approval-секрету. `n` — заявка уничтожается.
4. Код одноразовый, живёт 5 минут, повторно не используется. Клиент видит только статусы
   `pending/approved/rejected/expired`.

Уведомление на телефон: `termux-notification --title "Элиан: подтверждение" --content "LOGIN @user 1234-5678"`.
Показ кода в уведомлении управляется `OWNER_NOTIFICATION_SHOW_CODE` — помните, что текст уведомления виден
на экране блокировки.

## 3. Сброс пароля без SMS и почты

Пользователь нажимает «Забыли пароль?» → создаётся заявка `PASSWORD_RESET` → вы подтверждаете `y` →
клиент получает одноразовый тикет и задаёт новый пароль. Все прежние сессии пользователя отзываются.

## 4. Модерация

- Жалобы: `GET /api/v1/admin/reports` (только для владельца/модератора, требуется вход).
- Аудит: `GET /api/v1/admin/audit`, метрики: `GET /api/v1/admin/metrics`.
- В чате: бан/разбан, роли, slow mode, закрепления, удаление сообщений — через интерфейс администратора чата.
- Публичного админ-интерфейса нет. Никаких HTTP-эндпоинтов для подтверждения заявок не существует — только stdin консоли.

## 5. Обслуживание

```bash
bash scripts/termux/status.sh                       # здоровье, размеры, батарея
bash scripts/backup/backup.sh                       # бэкап + проверка целостности
node apps/server/dist/tools/backup.js list          # список архивов
bash scripts/backup/restore.sh <архив>              # восстановление
node apps/server/dist/tools/migrate.js              # применить миграции вручную
node apps/server/dist/tools/seed.js                 # демо-данные (только для разработки)
```

Ротация и очистка (планировщик, каждые 15 с):
- истёкшие заявки на подтверждение удаляются;
- истёкшие сессии отзываются;
- «осиротевшие» медиа без ссылок из сообщений чистятся;
- истёкшие истории архивируются/удаляются.

## 6. Частые задачи

**Заблокировать спамера.** В интерфейсе чата: профиль участника → «Заблокировать». Глобально: `POST /api/v1/blocks/:id`.

**Сделать публичный канал.** При создании чата включите «Публичный» и задайте `@адрес`; канал попадёт в поиск.

**Передать владение группой.** `POST /api/v1/chats/:id/transfer { newOwnerId }` — доступно текущему владельцу.

**Посмотреть, что происходит.** `bash scripts/termux/logs.sh server 200` — логи структурированные (pino),
с маскированным IP и вырезанными секретами.

## 7. Если что-то сломалось

| Проблема | Действия |
|---|---|
| сервер не стартует | `logs.sh server`; чаще всего занят порт или не совпал ключ БД |
| «Шифрование базы не подтверждено» | вернуть `DB_ENCRYPTION=required` и файл `db_key.key`; не отключайте шифрование «чтобы запустилось» |
| забыт пароль владельца | восстановление идёт той же процедурой `PASSWORD_RESET`, подтверждается в консоли |
| нужен перенос на новый телефон | скопировать `~/.elian/secrets`, `~/.elian/data` и `~/.elian/elian.env`, затем `start.sh` |
