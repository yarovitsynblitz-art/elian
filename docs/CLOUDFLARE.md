# Cloudflare Tunnel для Элиана

Туннель даёт публичный HTTPS/WSS без проброса портов и без белого IP. Сервер при этом слушает
только `127.0.0.1:3000` — снаружи его видно исключительно через `cloudflared`.

## 1. Quick Tunnel (быстро, без аккаунта)

```bash
ELIAN_TUNNEL_MODE=quick bash scripts/termux/bootstrap.sh
```

- Адрес вида `https://<случайное-имя>.trycloudflare.com`, живёт, пока работает процесс `cloudflared`.
- Адрес меняется после перезапуска. Подходит для «попробовать и показать друзьям».
- Аккаунт Cloudflare не нужен, но и гарантий SLA нет.

### Если открывается «Error 1033» / «Cloudflare Tunnel error»

Это значит, что ссылка в закладке **устарела**: у Quick Tunnel адрес привязан к процессу
`cloudflared`, и после перезапуска, обновления, перезагрузки телефона или пробуждения из
сна у туннеля уже другое имя. Сам сервер и база при этом целы.

Что делать (на телефоне, в Termux):

```bash
elian url          # актуальная ссылка
elian status       # заодно покажет, жив ли туннель и менялся ли адрес
elian start        # если туннель не запущен
```

Начиная с этой версии адрес **не теряется молча**: туннель работает под супервизором
(сам поднимается после сбоя), текущий адрес пишется в `~/.elian/public-url.txt`, история — в
`~/.elian/public-url.history`, а при смене адреса в шторке Android появляется уведомление
«Элиан: адрес изменился».

Постоянная ссылка, которую не нужно обновлять, — только у именованного туннеля (раздел 2):
`bash scripts/cloudflare/setup-named-tunnel.sh`, затем `ELIAN_TUNNEL_MODE=named` в `~/.elian/elian.env`.

## 2. Именованный туннель (постоянный домен)

Что нужно от вас (Cloudflare не даёт это сделать без интерактивного входа в аккаунт — и правильно):

1. Домен, добавленный в Cloudflare (NS домена указывают на Cloudflare).
2. `Zero Trust → Networks → Tunnels → Create a tunnel`, тип **Cloudflared**.
3. В туннеле: `Public Hostname` → например `elian.example.com`, сервис — `http://127.0.0.1:3000`.
4. Скопировать токен из команды установки (он начинается с `eyJ…`).

Затем:

```bash
bash scripts/cloudflare/setup-named-tunnel.sh     # скрытый ввод токена, сохранение в файл 600
bash scripts/termux/restart.sh
```

Альтернатива без интерактивного ввода (например, из вашего секрет-менеджера):

```bash
CLOUDFLARE_TUNNEL_TOKEN='<токен>' bash scripts/cloudflare/setup-named-tunnel.sh
```
Токен читается из переменной окружения/скрытого ввода и **никогда не попадает в argv**, историю команд или логи.

### Проверка после настройки

```bash
elian tunnel            # токен, домен, DNS, локальный сервер, публичный health
elian tunnel --live     # то же + реально поднять cloudflared на 25 с
```

Скрипт говорит по-русски, что именно не так: токен не от туннеля, домен ещё не делегирован
на Cloudflare (в `NS` видны чужие серверы), публичный хостнейм не создан, сервис в Public Hostname
указывает не на тот порт.

## 3. Почему нет Cloudflare Access

Access (SSO перед приложением) ломает PWA, WebSocket-авторизацию и push-подписки, а также заставляет
пользователей проходить второй вход. Модель безопасности Элиана другая: доступ к интерфейсу открыт,
но **каждый вход подтверждает владелец сервера в консоли Termux**. Админ-панели по HTTP нет вообще —
консоль владельца живёт только в tmux на телефоне.

## 4. Заголовки и IP

- `cloudflared` передаёт реальный IP в `CF-Connecting-IP`; сервер доверяет ему только при
  `TRUST_CLOUDFLARE_PROXY=true` и никогда не берёт произвольный `X-Forwarded-For`.
- В логах и админ-выводе IP маскируется.

## 5. Проверка

```bash
curl -fsS https://<ваш-домен>/api/v1/health
curl -fsS -o /dev/null -w '%{http_code}\n' https://<ваш-домен>/
bash scripts/termux/logs.sh tunnel | tail -20
```

В логе туннеля должны быть строки `Registered tunnel connection`. Если домен не открывается:

- DNS-запись `elian` должна быть CNAME на `<tunnel-id>.cfargotunnel.com` (Cloudflare создаёт её сам при добавлении Public Hostname);
- проверьте, что сервис в туннеле — `http://127.0.0.1:3000`, а не `https://`;
- телефон не должен «спать»: `bash scripts/termux/status.sh`.

## 6. Ограничения

- Бесплатный Cloudflare не гарантирует скорость для больших файлов; медиа лучше держать до нескольких десятков МБ.
- WebSocket-соединения стабильны, но при плохой сети клиент автоматически переподключается (реализовано в PWA).
- Cloudflare видит TLS-трафик на границе (это не E2E; сервер тоже видит открытый текст — см. `SECURITY.md`).
