  (и с `isOutgoing`/`byMe` от лица отправителя) → у получателя не обновлялся список и «чужие» сообщения
  отображались как свои. Теперь доставка персональная, состояние считается для каждого получателя.

## 2. Живой смоук production-сборки

```
$ node scripts/smoke/live-smoke.mjs
Итог: 39/39 проверок успешно, 2.9 с
```

Скрипт поднимает настоящий `dist/index.js` во временном каталоге (SQLCipher, реальные ключи) и проходит:
health → раздача PWA/manifest/sw.js → 401 у анонима → регистрация (202, заявка) → до подтверждения войти нельзя →
`y` из stdin консоли владельца → `approved` → обмен заявки на сессию → CSRF-cookie и 403 без заголовка →
повторный обмен отклонён → создание группы → сообщение с entities → реакция → поиск (глобальный и по чату) →
загрузка медиа и побайтовая сверка при скачивании (расшифровка) → папка → история → ICE-конфиг → экспорт →
диагностика → невозможность публичного подтверждения → Socket.IO доставка → выход → 401 после выхода →
БД на диске **без** SQLite-заголовка (шифрование подтверждено) → права секретов 600 →
пароль и код отсутствуют в логах и ответах.

Особенности: обвязка `scripts/e2e/run-e2e.mjs` запускает **настоящий** сервер и «печатает» `y`/`n` в его stdin
(так владелец одобряет заявки в Termux). Сценарии: два независимых браузерных контекста, обмен сообщениями в
реальном времени, реакции, редактирование, поиск по чату, мобильная раскладка (390×844), отказ заявки,
проверка что клиент не видит код подтверждения, сохранение темы/приватности после перезагрузки.

Проблемы, найденные E2E и исправленные:
- бесконечный ре-рендер из-за селектора zustand, создающего новый массив (React error #185);
- кнопка «назад» на мобильной раскладке не возвращала к списку чатов;
- доступное имя кнопки реакции включало эмодзи (нестабильный a11y-контракт) — вынесено в `aria-hidden`.

## 5. Установка на «чистом» устройстве (эмуляция Termux-пути)

Bootstrap-скрипт прогнан в чистом каталоге (`HOME=/tmp/boot-home`, пустые данные и секреты), режим без tmux
(в Termux используется tmux, здесь — nohup-фолбэк):

- первый запуск: установка зависимостей, сборка, генерация ключей, миграции, **реальный Quick Tunnel Cloudflare**;
- публичный адрес получен и проверен извне:
  `GET https://arbitration-specialties-fairfield-classical.trycloudflare.com/api/v1/health` →
  `{"status":"ok","encryptionAtRest":true}`; `/` → 200 (PWA); `/api/v1/config` → брендинг и лимиты;
- второй и третий запуски: `EXIT=0`, зависимости не переустанавливались (hash lock-файла), БД
  побайтово идентична (`md5` до/после), сделан страховочный бэкап перед изменениями;
- **установка из релизного архива** (`scripts/release/make-release.sh` → `elian-1.0.0.tar.gz`, 1.7 МБ) в пустой
  `HOME`: `bootstrap.sh` прошёл 9/9 шагов за 183 с (npm ci + сборка + миграции 3/3 + запуск), после чего
  `health` = `{"status":"ok","encryptionAtRest":true}`, `/` и `/manifest.webmanifest` → 200, заголовок файла БД —
  случайные байты (SQLCipher), три секрета с правами 600. `start.sh` пишет в PID-файл pid самого node,
  `stop.sh` гасит и сервер, и туннель (0 оставшихся процессов), `status.sh` берёт порт из конфигурации;
- бэкап/восстановление: `scripts/backup/backup.sh` → архив `.elnb` + `verify` → `restore.sh` вернул БД
  и сохранил `elian.db.before-restore-*`.

Релизный архив собирается командой `bash scripts/release/make-release.sh`: она печатает и SHA-256, и готовый
однострочник установки с этой суммой — публикуйте архив и сумму вместе.

## 6. Что НЕ проверено автоматически

- Реальный телефон с Android (архитектура, «усыпление» процесса, разрешение микрофона/камеры в WebView).
- Именованный Cloudflare-туннель (требует аккаунта владельца; Quick Tunnel проверен живьём).
- Звонки между двумя реальными устройствами через NAT (нужен TURN-сервер).
- Web Push на реальных подписках (VAPID генерируется, подписка и API проверены; доставка зависит от браузера).
- iOS/Safari, Firefox, WebKit (E2E — Chromium; вёрстка адаптивная, но браузеры не гонялись).
- Нагрузочное тестирование (сотни одновременных соединений).

## Установка из GitHub (проверено)

Публичный репозиторий: https://github.com/yarovitsynblitz-art/elian (релиз `v1.0.0` с архивом и `.sha256`).

| Проверка | Результат |
|---|---|
| `git clone --depth 1` без авторизации | ок |
| `bootstrap.sh` из клона в чистом `$HOME` | EXIT=0, 9/9 шагов, ~135 с |
| `npm ci` с компиляцией `better-sqlite3-multiple-ciphers` из исходников | ок (после фикса `npm_config_nodedir`) |
| `health` после установки | `{"status":"ok","database":"ok","encryptionAtRest":true}` |
| скачивание архива из релиза + сверка `.sha256` | ок, 696 541 байт |

Найдено и исправлено в этом прогоне:
- **`node-gyp` тянул заголовки Node из интернета** → на Termux это лишняя точка отказа. Теперь при наличии
  `$PREFIX/include/node` выставляется `npm_config_nodedir`, сборка идёт по локальным заголовкам.
- **ошибка `npm ci` не показывала причину** (вывод уходил в `tail -5`) → теперь лог пишется в
  `~/.elian/logs/deps.log`, при сбое печатаются последние 25 строк и подсказка `pkg install -y python make clang`,
  плюс один автоматический повтор.
