# Ограничения Элиана (честно и без маркетинга)

## Платформа и железо

1. **Один телефон — один сервер.** SQLite в WAL-режиме отлично держит десятки пользователей, но это не кластер:
   нет репликации, нет горизонтального масштабирования, нет отказоустойчивости. Упал телефон — упал мессенджер.
2. **Android усыпляет процессы.** Без `termux-wake-lock`, зарядки и разрешения «без ограничений» сервер будет пропадать.
   Это ограничение ОС, а не кода.
3. **Мобильный интернет/Cloudflare** добавляют задержку. Медиа на десятки мегабайт качаются медленно.
4. **Хранилище телефона.** Медиа растут быстро; встроенная чистка «осиротевших» файлов есть, но следить за местом нужно.

## Шифрование

5. **Нет E2E.** Сервер расшифровывает сообщения в памяти. Шифрование — только «на диске» (SQLCipher + AES-256-GCM).
   Секретных чатов, self-destruct сообщений и проверки ключей нет.
6. **Ключи на том же устройстве.** Если телефон разблокирован и злоумышленник имеет доступ к Termux, ключи доступны.
7. **Бэкапы** шифруются отдельной фразой, но по умолчанию эта фраза лежит рядом (в `secrets/`). Для защиты от кражи
   устройства фразу нужно вынести вручную.

## Звонки

8. **1:1 звонки работают** (WebRTC, сигнализация через Socket.IO), но без TURN-сервера часть сетей (симметричный NAT,
   некоторые мобильные операторы) соединиться не сможет. TURN настраивается через `TURN_URLS/TURN_USERNAME/TURN_CREDENTIAL`
   и требует отдельного сервера (например, coturn) — на телефоне рядом с сервером его не поднять осмысленно.
9. **Групповые звонки не реализованы.** Нужен внешний SFU (LiveKit/Janus/mediasoup). В интерфейсе это честно отмечено.

## Функции, требующие внешних сервисов

10. **Поиск GIF** — нужен ключ провайдера (`GIF_PROVIDER_URL`, `GIF_PROVIDER_KEY`, например Tenor). Без него функция
    возвращает «не настроено», а не поддельные результаты.
11. **Web Push на iOS** работает только для установленной PWA (iOS 16.4+) и с ограничениями; на Android — стабильно.
12. **mini apps** (веб-приложения внутри чата) — есть API ботов и песочница-iframe в планах, но интерфейса mini apps
    пока нет: боты работают через HTTP-API и команды, а встроенных сторонних приложений нет.

## Функции со статусом «частично»

13. **Темы в группах (topics)**, **реакции-анимации**, **премиум-косметика** — не реализованы (см. матрицу в `FEATURES.md`).
14. **Статистика канала** считается на сервере (`GET /api/v1/chats/:id/stats`), в клиенте показывается частично.
15. **Журнал действий чата** (`/chats/:id/audit`) и **заявки на вступление** доступны через API; в интерфейсе
    управления участниками показаны не все сценарии.
16. **Отложенные сообщения** создаются API (`scheduled_at`), но в композере нет отдельной кнопки «отправить позже».
17. **Стикеры**: сервер отдаёт паки и стикеры, в клиенте нет полноценного пикера — стикер можно отправить как медиа-вложение.
18. **QR-код профиля**: есть публичная ссылка `/u/<username>`, генерации QR в клиенте нет.
19. **Черновики** синхронизируются через API и локально; конфликты решаются «последняя запись побеждает».

## Ограничения дизайна

20. Один публичный домен на сервер; мультитенантности нет.
21. Регистрация всегда требует подтверждения владельцем (это принцип, а не недоработка). При `REQUIRE_OWNER_APPROVAL=false`
    сервер работает без подтверждений — но это ослабляет модель, включайте осознанно.
22. Мобильное приложение — PWA. Нативные сборки (Capacitor/TWA) возможны, но не входят в поставку.
23. Локализация: русский и английский. Часть системных сообщений сервера остаётся на русском.
24. **Argon2id работает в WebAssembly, а не нативно.** На телефоне это избавляет от компилятора C++,
    но хэш считается на ~30 % медленнее; для входа это десятки миллисекунд, для перебора паролей — только плюс.
25. **`better-sqlite3-multiple-ciphers` всё ещё собирается из исходников** на Termux (нужны `clang`, `make`, `python`).
    Без этого шифрование БД (SQLCipher) недоступно, поэтому запасного пути нет.
